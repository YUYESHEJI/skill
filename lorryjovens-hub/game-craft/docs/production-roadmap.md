# 圣斗士游戏生成器 - 生产级升级路线图

> 从 MVP 验证到生产级产品的完整演进路径
> 预计周期：3-6 个月 | 团队规模：2-4 人

---

## 一、当前状态评估

### 1.1 核心优势（已验证）
- ✅ AI 图像生成流程跑通（Gemini API 集成）
- ✅ 动作序列帧自动生成概念验证
- ✅ 关卡资产程序化生成
- ✅ 可运行的游戏引擎原型
- ✅ 用户界面交互流程完整

### 1.2 核心痛点（需解决）
- 🔴 API Key 暴露在前端，存在安全风险
- 🔴 无用户系统和数据持久化
- 🔴 无后端服务，无法扩展
- 🔴 代码无类型安全，无测试
- 🔴 生成失败无重试和降级机制
- 🔴 大文件（图像）处理效率低

## 三、分阶段实施路线图

### 阶段一：基础设施搭建（第 1-4 周）

**目标：建立安全可靠的后端基础设施**

#### 1.1 后端框架搭建
- [ ] 初始化 Node.js + Express + TypeScript 项目
- [ ] 配置 ESLint + Prettier + Husky 代码规范
- [ ] 搭建项目目录结构（MVC 或分层架构）
- [ ] 配置环境变量管理（dotenv + 多环境配置）

#### 1.2 数据库设计
- [ ] 设计 PostgreSQL 数据库 Schema
  - users 表（用户信息）
  - projects 表（项目/游戏配置）
  - assets 表（生成的资产元数据）
  - generation_tasks 表（生成任务记录）
- [ ] 配置 ORM（Prisma 或 TypeORM）
- [ ] 编写数据库迁移脚本
- [ ] 设置本地开发数据库（Docker Compose）

#### 1.3 用户认证系统
- [ ] 实现 JWT 认证机制
- [ ] 用户注册/登录 API
- [ ] 密码加密（bcrypt）
- [ ] 会话管理和 Token 刷新
- [ ] 第三方登录（Google OAuth）

#### 1.4 API 网关和代理
- [ ] 实现 Gemini API 代理转发
- [ ] API Key 安全存储（环境变量 + 加密）
- [ ] 请求速率限制（express-rate-limit）
- [ ] CORS 配置
- [ ] 请求/响应日志中间件

#### 1.5 文件存储服务
- [ ] 接入阿里云 OSS 或 AWS S3
- [ ] 实现文件上传/下载 API
- [ ] 图片压缩和格式转换（Sharp）
- [ ] CDN 配置

**里程碑交付物：**
- 可运行的后端服务
- 用户注册登录功能
- API Key 安全代理
- 文件上传存储能力

**目标：将前端逻辑迁移到后端，实现前后端分离**

#### 2.1 生成服务后端化

- [ ] 实现异步生成任务（Bull/BullMQ）

- [ ] 生成任务状态管理（pending/running/completed/failed）
- [ ] 失败重试机制（指数退避）

## 四、技术选型建议

### 前端技术栈
| 技术 | 选型 | 理由 |
|------|------|------|
| 框架 | React 18 + TypeScript | 生态成熟，类型安全 |
| 构建工具 | Vite | 快速开发体验 |
| 状态管理 | Zustand | 轻量简洁 |
| UI 组件 | shadcn/ui + Tailwind CSS | 高度可定制 |
| 路由 | React Router v6 | 标准方案 |
| 游戏引擎 | PixiJS | 2D 渲染性能优秀 |
| 实时通信 | Socket.IO | 成熟稳定 |

### 后端技术栈
| 技术 | 选型 | 理由 |
|------|------|------|
| 运行时 | Node.js 20 LTS | 成熟稳定 |
| 框架 | Express + TypeScript | 简单灵活 |
| ORM | Prisma | 类型安全，开发效率高 |
| 数据库 | PostgreSQL 15 | 关系型数据首选 |
| 缓存 | Redis 7 | 高性能缓存和队列 |
| 任务队列 | BullMQ | 基于 Redis，功能丰富 |
| 文件存储 | 阿里云 OSS | 国内访问快 |
| 认证 | JWT + bcrypt | 标准方案 |

### 基础设施
| 服务 | 选型 | 理由 |
|------|------|------|
| 容器 | Docker + Docker Compose | 标准化部署 |
| CI/CD | GitHub Actions | 免费且集成好 |
| 监控 | Prometheus + Grafana | 开源成熟 |
| 日志 | Winston + Loki | 结构化日志 |
| 错误追踪 | Sentry | 前端后端全覆盖 |
| CDN | 阿里云 CDN | 国内加速 |

## 六、风险管控

### 6.1 技术风险
| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| Gemini API 不稳定 | 中 | 高 | 多模型备选、请求重试、降级策略 |
| 生成质量不达预期 | 高 | 中 | 提示词优化、后处理、人工审核 |
| 并发性能瓶颈 | 中 | 高 | 任务队列、水平扩展、限流 |
| 数据丢失 | 低 | 极高 | 自动备份、多副本、定期演练 |

### 6.2 业务风险
| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| 用户需求变化 | 高 | 中 | 敏捷迭代、用户反馈循环 |
| 竞品出现 | 中 | 中 | 持续创新、建立壁垒 |
| 成本控制 | 中 | 高 | 用量监控、预算告警、优化策略 |
| 合规风险 | 低 | 高 | 内容审核、用户协议、数据合规 |
